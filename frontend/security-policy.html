Security Policy

How HealiiX safeguards patient health records, protects doctor credentials, and ensures continuous service resilience across Bangladesh.

SOC 2 Type II Principles • TLS 1.3 Certified • Cloudflare Protected

Cryptographic Transit

Security Architecture

1 Encryption at Rest & Transit

HealiiX enforces cryptographic controls across the entire data lifecycle. All client interactions with our API gateways and frontend clients are strictly encrypted over TLS 1.3 using modern cipher suites.

At rest, sensitive patient data and appointment records are persisted on MongoDB Atlas clusters with hardware-accelerated AES-256 volume encryption. Production backups are continuously encrypted and geographically redundant.

2 Authentication & Token Security

User passwords are protected using bcrypt adaptive hashing with a minimum of 10 rounds. Password reset requests mandate time-limited, single-use 6-digit numeric OTPs dispatched over secured transactional email nodes.

Key Token Security Protections:

• High-entropy JSON Web Tokens (JWT) signed with secret keys.

• Automatic token expiration requiring re-authentication.

• Dedicated administrator login routes with strict role enforcement to eliminate privilege escalation vectors.

3 Doctor BMDC Verification Protocol

Protecting patients from unqualified or fraudulent medical practitioners is a core principle of HealiiX. Before any doctor profile is activated:

  1. The practitioner’s BMDC registration number is checked against official Bangladesh medical records.
  2. High-resolution scans of the BMDC practicing certificate and government-issued national ID are manually inspected by the HealiiX Medical Board verification desk.
  3. Chamber contact lines are verified to ensure physical clinical presence.
  4. Only verified profiles receive the public Verified Practitioner badge.

4 Database & Cluster Safeguards

Production database instances run in isolated Virtual Private Clouds (VPC) with automated IP allowlists. Direct public database access is strictly prohibited.

Our application backends implement automated rate limiting and request body parsers to defend against DDoS attacks, slowloris exploits, and automated brute-force credential stuffing.

5 Image & Media Sanitization Pipeline

To eliminate image-borne exploits (e.g. steganography, embedded malicious scripts, and oversized buffer overruns), HealiiX enforces a strict pipeline:

  • All user-uploaded avatars and certificate documents are stripped of EXIF metadata.
  • Images are aggressively re-encoded into optimized WebP formats before cloud storage.
  • Database schemas strictly reject raw Base64 data strings to keep database query footprints lean and safe.

6 Responsible Vulnerability Disclosure

We welcome security researchers and ethical hackers who assist in keeping HealiiX secure. If you discover a potential vulnerability, please report it responsibly:

• Email full details and proof-of-concept steps to: healiix@alrifatsabbir.me

• Please allow us a reasonable window (48–72 hours) to reproduce and remediate the issue before public disclosure.

• Do not access or alter any live patient data or doctor credentials during testing.
